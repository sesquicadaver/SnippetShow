Нижче наведено повне технічне завдання (ТЗ) на розробку десктопної утиліти для Linux. Документ структурований так, щоб за ним можна було вести розробку самостійно або передати його команді.

Технічне завдання (ТЗ)


Проєкт: Linux Command Wiki & Script Builder


1. Загальні відомості та мета проєкту

Мета проєкту: Створити швидку, легковагову десктопну утиліту для ОС Linux, яка виконує роль локальної інтерактивної бази знань (табличного Wiki) щодо консольних програм, їхніх параметрів (man), персональних користувацьких команд (сніпетів) та конструктора shell-скриптів.
Цільові платформи: Популярні дистрибутиви Linux та їхні похідні:
• Сімейство Debian/Ubuntu (Ubuntu, Linux Mint, Pop!_OS, Debian).
• Сімейство Arch Linux (Arch, Manjaro, EndeavourOS).
• Сімейство RHEL/Fedora (Fedora, openSUSE).
Рекомендований технологічний стек:
• Бекенд: Go (Golang 1.22+).
• Графічний інтерфейс (GUI): Wails v2 (HTML5, CSS3, Vanilla JS або Svelte).
• База даних: SQLite (драйвер modernc.org/sqlite без C-залежностей, з увімкненим модулем повнотекстового пошуку FTS5).
• Формат постачання: Один автономний бінарний файл (ELF) без зовнішніх залежностей (окрім стандартного системного webkit2gtk).

2. Архітектура системи та логіка даних


2.1. Модуль сканування пакетів та бінарників (System Scanner)

Програма повинна визначати доступний пакетний менеджер у системі та збирати два набори даних:
1. Встановлені програми:
	• Сканування системних директорій $PATH (/usr/bin, /bin, /usr/local/bin, ~/.local/bin) для отримання переліку реальних виконуваних файлів.
	• Зіставлення з базою пакетного менеджера (dpkg-query для Debian/Ubuntu, pacman -Q для Arch, rpm -qa для Fedora) для отримання версії пакета та офіційного короткого опису.
2. Всі програми (каталог репозиторію):
	• Читання локального кешу репозиторіїв (apt-cache / /var/lib/apt/lists/*, pacman -Sl, dnf list) для отримання назв та описів програм, доступних для встановлення в цільовому дистрибутиві.

2.2. Модуль індексації документації (Man Parser)

• Отримання короткого опису утиліти через виклик man -f <cmd> (або whatis).
• Витягування повного тексту документації без керуючих символів форматування (MANWIDTH=1000 man -P cat <cmd> | col -bx).
• Парсинг секцій OPTIONS, COMMANDS або FLAGS за допомогою регулярних виразів для виділення пар: [Прапорець/Команда] — [Опис].
• Багатопотокова обробка (воркер-пул на 4–8 горутин) для швидкого оновлення бази без блокування інтерфейсу.

2.3. Логіка інкрементального оновлення («Оновити індекс»)

• Перший запуск: Виконується швидке сканування встановлених бінарників і формування базового списку програм. Повний парсинг man-сторінки може відбуватися «на льоту» при кліку на програму або масово за бажанням користувача.
• Кнопка «Оновити індекс»:
	• Перевіряє поточний список встановлених програм та їхні версії проти записів у локальній БД.
	• Додає нові програми та парсить їхні man-сторінки.
	• Перепаршує man-сторінки для програм, версія яких змінилася.
	• Позначає видалені програми прапорцем is_installed = 0, але не видаляє прив'язані до них користувацькі команди.

3. Структура бази даних (SQLite)

База даних зберігається у директорії ~/.local/share/linux-cmd-wiki/wiki.db.
1. Таблиця programs:
	• id (INTEGER PRIMARY KEY)
	• name (TEXT UNIQUE) — назва команди.
	• package_name (TEXT) — назва системного пакета.
	• summary (TEXT) — опис призначення програми.
	• version (TEXT) — версія пакета.
	• is_installed (BOOLEAN) — статус встановлення (1 — так, 0 — ні).
	• man_parsed (BOOLEAN) — чи розпарсена man-сторінка.
2. Таблиця man_commands:
	• id (INTEGER PRIMARY KEY)
	• program_id (INTEGER, FK -> programs.id)
	• flag (TEXT) — синтаксис прапорця або підкоманди.
	• description (TEXT) — офіційний опис із man.
3. Таблиця user_snippets (Користувацькі команди):
	• id (INTEGER PRIMARY KEY)
	• program_id (INTEGER, FK -> programs.id)
	• title (TEXT) — коротка назва сценарію (напр., «Стиснути відео в H.265»).
	• command (TEXT) — повний рядок команди.
	• tags (TEXT) — теги для швидкого пошуку.
	• created_at (DATETIME)
4. Таблиця custom_scripts (Збережені скрипти):
	• id (INTEGER PRIMARY KEY)
	• name (TEXT) — назва скрипту.
	• script_body (TEXT) — текст bash-скрипту.
	• updated_at (DATETIME)
5. Індекс programs_fts (SQLite FTS5):
	• Віртуальна таблиця для миттєвого повнотекстового пошуку за назвою програми, її описом, прапорцями та сніпетами користувача.

4. Функціональні вимоги до інтерфейсу (UI/UX)

Інтерфейс має бути побудований за принципом табличного Wiki з розділенням на три основні зони (панелі).

4.1. Верхня панель керування (Toolbar)

• Перемикач режиму (Radio buttons):
	• (•) Встановлені програми (за замовчуванням).
	• ( ) Всі програми (повний каталог дистрибутива).
• Рядок пошуку: Живий миттєвий пошук із підтримкою фільтрації за назвою утиліти або ключовими словами призначення (напр., «архів», «мережа», «ffmpeg»).
• Алфавітний фільтр: Смуга літер A–Z + 0–9 + Всі для швидкої навігації за першою літерою назви.
• Кнопка «Оновити індекс»: Запускає фонову актуалізацію бази з відображенням прогрес-бару та статусу (напр., «Оновлено 14 пакетів»).

4.2. Ліва панель: Список програм (Навігатор)

• Відображає відфільтрований список програм у вигляді компактної таблиці: [Назва] | [Короткий опис] | [Статус].
• Візуальне розрізнення встановлених та невстановлених програм (у режимі «Всі програми»).
• Якщо обрана невстановлена програма, у центральній панелі відображається її опис із репозиторію та команда для встановлення (напр., sudo apt install <pkg>).

4.3. Центральна панель: Табличне Wiki обраної програми

Містить дві вкладки або дві суміжні таблиці:
1. Офіційні команди та прапорці (man):
	• Колонки: [Чекбокс для скрипту] | [Прапорець/Команда] | [Опис із документації] | [Дії].
	• Швидкий фільтр всередині прапорців поточної програми.
	• Кнопка перегляду сирого тексту man-сторінки (Raw Man View) на випадок, якщо автоматичний парсер пропустив складний блок тексту.
2. Мої команди (Користувацькі сніпети):
	• Окрема таблиця/колонка для збереження власних перевірених команд до обраної програми.
	• Кнопка «+ Додати команду» (форма: Назва, Команда, Теги).
	• Можливість редагувати та видаляти власні записи.
	• Кнопки дій біля кожного рядка (як в офіційних, так і у власних командах):
		• Копіювати (Copy): Копіює команду в системний буфер обміну (підтримка X11 та Wayland) зі спливаючим сповіщенням «Скопійовано».
		• Запустити (Run): Відкриває системний термінал користувача ($TERMINAL, x-terminal-emulator, gnome-terminal, konsole, xfce4-terminal) і передає команду на виконання з утриманням вікна відкритим після завершення (bash -c "<command>; exec bash").
		• Додати в скрипт (+ Script): Додає команду в конструктор скриптів.

4.4. Права висувна панель: Конструктор скриптів (Script Builder)

• Накопичує команди, обрані користувачем з різних програм.
• Можливість змінювати порядок команд (кнопки Вгору/Вниз або Drag-and-Drop).
• Вбудований текстовий редактор із базовим підсвічуванням синтаксису bash для ручного коригування, додавання циклів, змінних чи конвеєрів (|, &&).
• Автоматичне додавання заголовка #!/usr/bin/env bash.
• Дії зі скриптом:
	• Копіювати весь скрипт у буфер обміну.
	• Запустити скрипт у терміналі.
	• Експортувати у файл .sh з автоматичним наданням прав на виконання (chmod +x).
	• Зберегти скрипт у внутрішню базу даних для повторного використання.

5. Нефункціональні вимоги

• Продуктивність: Запуск холодного старту програми — не більше 1 секунди. Пошук по базі з 3000 програм — не більше 50 мс.
• Споживання ресурсів: У режимі очікування програма повинна споживати не більше 60–80 МБ оперативної пам'яті.
• Безпека: Перед прямим запуском команди або скрипту в терміналі (кнопка Run) програма повинна показувати діалогове вікно підтвердження, якщо команда містить потенційно небезпечні конструкції (rm -rf, dd, mkfs, sudo).
• Резервне копіювання: Можливість експорту та імпорту таблиць user_snippets та custom_scripts у формат JSON, щоб користувач міг переносити свою базу напрацювань між різними ПК.

6. Етапи розробки (Roadmap)

1. Етап 1 (Core & DB): Ініціалізація проєкту Go + Wails, створення схеми SQLite, написання сканера бінарників та багатопотокового парсера man-сторінок.
2. Етап 2 (Read-Only Wiki UI): Верстка інтерфейсу табличного Wiki, реалізація перемикача «Встановлені / Всі», пошуку FTS5, алфавітного фільтра та кнопки «Оновити індекс».
3. Етап 3 (User Snippets & Actions): Додавання CRUD-операцій для колонки «Мої команди», реалізація копіювання в буфер обміну (X11/Wayland) та запуску в системному терміналі.
4. Етап 4 (Script Builder & Polish): Реалізація конструктора скриптів, експорту/імпорту JSON-бекапів, тестування бінарної збірки на Ubuntu, Arch та Fedora.
